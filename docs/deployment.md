# Deploy the interactive app on Render

This deployment creates a Python web service with HTTPS, password access, and a persistent 1 GB disk for SQLite. It selects Render's **paid Starter plan**; review the service and storage charges shown by Render before confirming. A free instance without persistent storage would lose the local database when replaced or redeployed.

## Launch

1. Create or sign in to your [Render account](https://dashboard.render.com/register).
2. Open [Deploy Signal on Render](https://render.com/deploy?repo=https://github.com/kanhao-bytedance/bytedance).
3. Connect GitHub and allow Render to read `kanhao-bytedance/bytedance` if prompted. If your repository is private, grant access only to that repository. Choose a workspace and review the Blueprint from `render.yaml` on `main`.
4. Review the paid plan and disk cost, then create the Blueprint resources using Render's confirmation action.
5. Open the `signal-voc` service and wait until its deployment is live. Render displays its actual HTTPS URL on the service page. Open that URL for the interactive dashboard.
6. When the browser asks you to sign in, use username `admin`. The password is generated by Render: reveal the `DASHBOARD_PASSWORD` value in the service's Environment settings. Do not post that password in chat, screenshots, or GitHub.

There is no live URL until the service has been created and deployed in your Render account. The deployment button is a configuration link, not the running website.

## What gets deployed

- `render.yaml`: Python 3.12 web service, `/health` check, Starter plan, persistent disk at `/var/data`.
- `requirements.lock.txt`: exact runtime dependency versions.
- `scripts/start.sh`: starts one Uvicorn worker on Render's assigned `PORT`.
- `DATABASE_URL=sqlite:////var/data/voc.db`: keeps feedback on the disk across process restarts and redeployments. Treat disk backups separately from Git backups; do not delete the service/disk without exporting required data.
- `REQUIRE_DASHBOARD_AUTH=true`: refuses to start without a configured password. Dashboard, API, documentation, and assets require authentication; `/health` remains available for the provider's readiness check.

This is a shared-workspace login for a small MVP, not a multi-user account system. Use the HTTPS URL Render provides. API clients use HTTP Basic authentication with the same username and password. Browser writes from other origins are rejected.

AI and Reddit credentials are optional. Manual entry, search, source evidence, and dashboard counts work immediately without them. If you add `OPENAI_API_KEY`, `OPENAI_MODEL`, `REDDIT_BEARER_TOKEN`, or `REDDIT_USER_AGENT`, use Render's secure Environment settings. No credential values belong in Git.

## Verify after launch

1. Open the service URL and sign in. The dashboard should load.
2. Add a feedback record with a unique source reference. It should appear once, marked unclassified if AI is not configured.
3. Search for its text and open it to inspect the original evidence.
4. Restart the service using Render, sign in again, and confirm the record remains.
5. `/health` should return `ok: true`. A successful build alone does not establish that these live checks passed.

## Troubleshooting

- **Repository not found:** grant the Render GitHub integration access to this repository.
- **Missing password startup error:** set `DASHBOARD_PASSWORD` in Render's Environment settings and redeploy. Do not disable required authentication.
- **Database write error:** confirm the disk is attached at `/var/data` and `DATABASE_URL` matches the Blueprint.
- **Schema mismatch on an existing database:** preserve the database and plan a migration. Do not delete customer feedback to make startup pass.
- **Unexpected AI or Reddit errors:** manual capture remains available; check credentials and approved API access for the affected integration.

## Reproduce the production startup check

```bash
python scripts/check_deployment.py
```

This uses a temporary database, starts on an available port, verifies login and feedback ingestion, restarts the process, confirms the record persists, and checks that hosted mode refuses to start without a password. It does not provision a Render service.

## Current validation

The local test suite covers the feedback workflow and hosted authentication, including rejected cross-origin writes and failure to start without a required password.
